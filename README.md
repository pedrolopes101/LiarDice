# LiarDice

A dice app for playing Liar's Dice (or anything else with dice) on iOS and Android, built with Expo (React Native).

## Features

- **Add / remove dice** with the `+` / `−` buttons (1–12 dice).
- **Roll** by pressing the *Roll* button **or by shaking the phone**.
- **Lock** button locks all dice at once — they keep their values and can't be rolled (by button or shake) until you press *Unlock*.
- **Cup (optional):** with *Hide dice after roll* on, the dice are covered by a cup after every roll. Press and hold the cup to peek; tap *Reveal* to show everyone (and *Cover* to hide them again).
- **Face counts:** how many dice show each face, handy for bidding. With *1s are wild* on, 1s count towards every other face.
- Each number has its own pip color — a **1 is red**.
- Dice-rolling sound, running total, roll animation and haptic feedback.

### Settings (⚙️, top right)

| Setting | Default | |
|---|---|---|
| Hide dice after roll | off | Cover the dice with the cup after every roll |
| 1s are wild | off | Count 1s towards every other face |
| Sound | on | Dice-rolling sound |
| Vibration | on | Haptic feedback |
| Keep screen on | on | Stop the screen turning off mid-game |
| Shake sensitivity | medium | Low / medium / high |

Settings and the number of dice are saved on the phone and restored the next time the app opens.

## Running it

```bash
npm install
npx expo start
```

Scan the QR code with the **Expo Go** app on your phone (shake detection needs a real device — simulators have no accelerometer).

```bash
npm test            # unit tests
npm run typecheck   # TypeScript
```

## Project layout

- `App.tsx` — main screen (header, dice count, board / cup, counts, lock and roll buttons)
- `src/components/DieView.tsx` — a single die with colored pips, lock state and spin animation
- `src/components/Cup.tsx` — the cup drawn over hidden dice
- `src/components/FaceCounts.tsx` — per-face counts
- `src/components/SettingsModal.tsx` — settings sheet
- `src/hooks/useShake.ts` — accelerometer-based shake detection (`expo-sensors`)
- `src/dice.ts` — dice helpers (rolling, counting faces)
- `src/settings.ts` — settings, defaults and on-device persistence
- `src/__tests__/` — unit tests
- `assets/sounds/dice-roll.mp3` — roll sound, generated by `scripts/make-roll-sound.py`
- `assets/*.png` — app icon set (dice cup + die), generated by `scripts/make-icons.py` from `assets/source/`

## Getting a test APK

Every push to `main` (and to `feature/**` branches) runs the **Build Android APK** GitHub Actions workflow: typecheck, unit tests, then an APK build. You can also start it manually from the *Actions* tab. When it finishes, download the `LiarDice-apk` artifact from the run page, unzip it and install the `.apk` on your Android phone (allow "install unknown apps" when asked).

That APK is signed with the debug key, so it is for testing only — not for the Play Store.

## Publishing to Google Play

Store builds are made with [EAS](https://docs.expo.dev/eas/), configured in `eas.json`:

- `production` builds a signed **Android App Bundle (.aab)**. EAS creates and keeps the upload key, and bumps the version code on every build (`autoIncrement`, with `appVersionSource: remote`).
- `preview` builds an installable APK signed with that same key, for sharing with testers.

```bash
npx eas-cli@latest login                                   # free expo.dev account
npx eas-cli@latest build --platform android --profile production
```

1. Create the app in the [Google Play Console](https://play.google.com/console) (one-time $25 developer fee). Fill in the store listing, privacy policy, content rating, target audience and data safety (the app collects no data).
2. **First release:** upload the `.aab` by hand to a testing track. Google requires the first upload to be manual.
3. **Later releases:** `npx eas-cli@latest submit --platform android --profile production` uploads the latest build to the *internal* track as a draft. This needs a Google Play service account key; EAS asks for it the first time.

The package name `com.pedrolopes.liardice` can't be changed after the first upload.
